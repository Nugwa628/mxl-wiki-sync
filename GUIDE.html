Keeping the wiki in step with the docs

When docs.median-xl.com updates (say, to Σ 2.15), this tool works out exactly which wiki pages need to change, shows you every change, and applies them — while keeping edits people made on the wiki by hand.

How it works

There are five steps. Two happen in Chrome to save copies of the docs and the wiki, one runs on your computer to compare them, and the last applies the update back in Chrome. Nothing on the wiki changes until step 5, and you see every change first.

The comparison uses the same converter that originally built the wiki pages, so if the docs haven't changed, it reports no changes at all. That's a good first test.

One-time setup

a

Unzip the folder somewhere permanent

For example Desktop\sugma\mxl-wiki-sync. Keep using the same folder each time. Its data folder is how the tool remembers what it made before, which is how it spots hand edits.

b

Install Python

Get Python 3.10 or newer from python.org/downloads. During install, tick "Add python.exe to PATH". That's the only option that matters.

The first time you run run_sync.bat it installs the two add-ons it needs (beautifulsoup4 and lxml) automatically.

c

Know how to open Chrome's Console

On any page, press F12 (or Ctrl+Shift+J) and click the Console tab. You'll paste scripts there and press Enter.

First paste only: Chrome blocks pasting into the Console until you type allow pasting and press Enter. After that, pasting works normally.

3 · Compare

Double-click run_sync.bat in the tool's folder. A black window opens and:

  • finds the newest docs and wiki snapshots in your Downloads folder,
  • builds every wiki page from the docs (about 10 seconds),
  • compares them with the wiki and prints a summary,
  • opens report.html in your browser.
Docs snapshot: C:\Users\you\Downloads\mxl-docs-snapshot-2026-11-02.json Wiki snapshot: C:\Users\you\Downloads\mxl-wiki-snapshot-2026-11-02.json Game version: Σ 2.15 1677 pages generated new pages 12 updated 57 (+482 version-number-only) merged w/ edits 3 CONFLICTS 1 (not in the update — see report) unchanged 1122 images to upload 9 Done. Stop if the report looks wrong. If hundreds of pages show strange changes (missing stats, broken tables, garbled text), the docs probably changed their page layout. Don't apply that update; the converter in generator\ needs adjusting first.

5 · Apply

  1. Open wiki.median-xl.com and make sure you're logged in.
  2. Open the Console, copy the script below (or open apply_update.js from the output folder), paste and press Enter.
  3. A panel appears in the bottom-right corner. Click Choose File and pick wiki-update.json from the output folder.
  4. Check the counts it shows match the report.
  5. Optional: tick dry run and click Start to see the list of what it would do without changing anything. Paste the script again for the real run.
  6. Untick dry run and click Start.
apply_update.js8.5 KB · also in the browser folder
Show the script

It uploads new images first, then edits pages about one per second (the wiki allows about 90 edits a minute). A large update of around 500 pages takes about 8–10 minutes. Leave the tab open while it runs.

  • Stop finishes the current page and stops. Nothing is left half-written. To continue later, take a new wiki snapshot and run steps 3–5 again; pages already done show as unchanged.
  • If the wiki says it's busy or rate-limited, the script waits and retries on its own.
  • At the end it saves wiki-update-result-<date>.json to Downloads, listing every page done, skipped or failed.
Built-in safety: "new page" edits can never overwrite an existing page, and "update" edits can never create one. A page someone edited after your wiki snapshot is skipped with the message changed on the wiki after the snapshot. Every edit is in the page history with the summary "Sync with docs.median-xl.com (Σ x.y)", so any of them can be undone from the wiki's history page.

5 · Apply with Special:Import (admins, alternative)

If your account has the import right (admins on this wiki do), you can load the whole update in a few seconds with the wiki's own import page instead of running apply_update.js. Steps 1–4 are the same. Every run also writes the files for this method:

output\sync-2.15-2026-11-02_1930\for-special-import\ pages-part01.xml ← the page updates, split into files of about 1.5 MB pages-part02.xml images-for-batchupload\ ← new images (only if there are any) pages-in-this-import.txt ← list of every page in the XML files

The XML files contain the same pages as wiki-update.json. Conflicts are already left out.

a

Take the wiki snapshot just before

Do steps 2–4 right before importing. The import protects pages that are edited after the wiki snapshot (see the safety note below). The fresher the snapshot, the less there is to catch up on afterwards.

b

Upload the images first

Skip this if there's no images-for-batchupload folder.

  1. Open Special:BatchUpload while logged in.
  2. Select every file in images-for-batchupload and drag them onto the drop area. The file names already match what the pages use, so don't rename them.
  3. Wait until each file shows a tick.
c

Import the XML files

  1. Open Special:Import. Use the section Import from an XML file.
  2. Choose pages-part01.xml.
  3. Interwiki prefix: type docs. The form requires a prefix; it's only used to label the imported edits.
  4. Leave Assign edits to local users unticked, unless you ran sync with --import-user YourName and want the edits under your own name.
  5. Optionally type a reason such as Sync with docs Σ 2.15, then click Upload file.
  6. The wiki lists each page with "1 revision" (imported) or "0 revisions" (already identical, nothing to do).
  7. Go back and repeat for pages-part02.xml and the rest, in order.
"File too large" or a timeout? Run the compare again with smaller files, e.g. run_sync.bat --import-part-mb 0.5, and import those instead.
d

Check the result

Take a fresh wiki snapshot (step 2) and run the compare again (step 3). It should report nothing left to do apart from any conflicts. If someone edited a page after your first snapshot, that page shows up again, and you can apply it the normal way.

Why a page edited after the snapshot is safe: every imported revision is dated at the time of your wiki snapshot. MediaWiki always keeps the newest revision as the current page. So if someone edited a page after the snapshot, their edit stays current and the imported text only goes into that page's history. This is the same protection apply_update.js gives.

Hand edits & conflicts

The tool keeps a copy of every set of pages it generates. Comparing that copy with the wiki tells it whether someone edited a page by hand:

The wiki page is…What happens
MissingCreated
Exactly what the tool made last timeReplaced with the new docs version
Hand-edited, and the docs changed a different partMerged: the hand edit stays, the docs change goes in
Hand-edited, and the docs changed the same linesConflict: left out of the update
Hand-edited, and the docs didn't change itLeft alone

For example, Assur's Bane was added by hand to the Sacred Uniques list. If 2.15 changes Earth Rouser's level on that same page, the new level goes in and the Assur's Bane row stays.

Resolving a conflict

For each conflicting page, the conflicts folder holds two files:

  • <Page>.docs-version.wiki: the page exactly as the docs would make it.
  • <Page>.merged-with-markers.wiki: everything merged, with the clashing parts marked like this:
<<<<<<< wiki (hand edit) +1100 Defense ======= +1200 Defense >>>>>>> docs

Open the page on the wiki, click Edit source and decide which version is right (or combine them). Open the .wiki files in Notepad to copy from them, and save. The next run will see the page as "hand edits kept" or "unchanged".

Pages it never touches

  • The seven class pages (Amazon … Sorceress). Their skill trees come from the game files, not the docs. If the docs class pages change, the report lists them under "Docs pages to check by hand".
  • Secret Items. Built from the game files.
  • The Main Page.
  • Pages written by hand, such as Assur's Bane, and anything else the tool didn't create.
  • Docs pages that were never converted (FAQ, OSkills, Monsters, …). Changes to them are listed so you can decide whether the wiki needs anything.

Options

Normally you just double-click run_sync.bat. For special cases, open a terminal in the folder (in Explorer, click the address bar, type cmd, press Enter) and add options:

CommandUse it when
python sync.py --docs FILE --wiki FILEYou want to use specific snapshot files.
python sync.py --version 2.15The version can't be read from the docs front page.
python sync.py --update-imagesYou also want to replace wiki images that differ from the docs.
python sync.py --recreateBring back pages the tool made earlier that someone deleted.
python sync.py --no-saveTest run that isn't remembered in data\history.
python sync.py --out D:\somewherePut the output folder somewhere else.
python sync.py --import-part-mb 0.5Make smaller Special:Import files, if the wiki rejects them as too large.
python sync.py --import-user YourNamePut your own name on the Special:Import edits (tick "Assign edits to local users" when importing).

run_sync.bat passes options through too, e.g. run_sync.bat --update-images.

FAQ

Can I run the comparison more than once?
Yes. It's safe to run as often as you like. Nothing changes on the wiki until you apply.
What if I compare but never apply?
Nothing happens. Next time, the tool still recognises the wiki's pages from earlier runs.
How do I undo an update?
Every edit is in the wiki's page history with the summary "Sync with docs.median-xl.com (Σ x.y)". Use "undo" or "restore" on that page's history. An admin can also mass-revert by that summary.
Does someone else need to install this to use it?
Only the person running steps 3–5. Anyone can do steps 1–2, but the files have to end up on the computer that runs run_sync.bat.
Will it ever delete pages?
No. Removed or renamed items only appear in the report under "No longer in the docs".
Can I move the folder to another computer?
Yes. Copy the whole folder, including data.
Why does a new version touch hundreds of pages?
Every item with a "Version history" box records which version the page is current for. On a new version, that number changes on every one of those pages. The report lists those under "Version number only".
